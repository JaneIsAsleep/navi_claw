## 推荐方向与范围

推荐在现有 Gateway、SQLite、作业队列和 Dialog 上完成这十项。最小方案是调整 CSS、删除按钮，再让模型使用更短的提示词；它无法解决每天自动生成、完整五条替换、第二次发送、目标确认及关联取消，因此不采用。也不引入第二套助理框架或后台服务。这轮最主要的风险在于模型输出与持久状态不一致，关键状态转换由 Gateway 校验并提交。

本轮保留六个主要入口、受保护的主对话、标题搜索、封存和解封、删除对话时取消关联提醒、封存期间转发主对话、CLI / Web 共享状态、现有审批和 Outbox。保留助手详情中的记忆、提醒、审批与活动。取消某目标只影响与该目标有真实关系的工作。

本计划审核并获准实施后，局部更新 [engineering/plans/Navi Product Refinement Plan.md](<Navi Product Refinement Plan.md>) 中的几个既有选择：搜索由独立页面改为弹窗；构想去掉可见时间与引用讨论；准备简报不再出现在动态和成果库；完成目标会结束关联追踪与提醒；分类入口立即开始引导。该旧计划第 131 行“旧标题不改写”与 R02 的自动摘要命名存在局部冲突，建议仅允许下文定义的可识别自动标题更新，手动标题和来源不明的旧标题继续保留。原计划文件保留，后续通过实施记录注明覆盖关系。

不扩大到任意 RSS / 网站、邮件和日历接入、全文搜索、云端虚拟机、Podcast、交易或外部通知。保持现有运行时扩展边界。Muse 中展示的邮箱监控、购物、退款等文案不能证明 Navi 已有这些能力，也不能作为新增范围。成果库的收敛不会删除导出审批和审计。

最关键的前提是：本机运行且能够访问现有模型和来源。电脑休眠或 Gateway 停止时，06:00 无法执行；恢复后只补最近一次应到生成。五条指成功生成后的有效批次，首次模型失败时显示真实空态，不编造五条占位；已有批次失败时继续保留。这个限制必须在用户可理解的位置说明。

## 应有的页面与行为

**对话、首轮标题和搜索，R01 / R02 / R07。** 桌面保留 76px 图标栏、240px 对话栏及约 820px 阅读宽度，头像在聊天面板自身的水平中心，不能把旁边的目标页算进居中区域。移除导航顶部的黑色 Navi 文字、顶部重复话题标题、返回标题搜索按钮。保留助手详情、发送、取消当前工作、消息复制、真实审批和封存状态提示。禁止用另一个固定摘要条重新占据顶部。

首条用户消息发送后，菜单使用短暂“新对话”状态，不显示前 30 字。第一轮成功回复落库后排入一次 session_meta 作业，产生不超过 16 字的主题标题，以及不超过 60 字的 display_abstract。摘要概括用户任务和本轮结果，忽略“这是临时测试”等包装前缀，不把任务编号、模型 ID 或工具错误当成话题名。主对话保持原名。标题任务不写聊天消息，也不触发提醒。

现有 sessions.summary 是长会话压缩上下文，包含受保护信息，禁止拿它当作菜单或搜索摘要，搜索接口也不返回它。手动重命名继续以 title_manual 为准，生成任务提交时再次校验，防止覆盖刚改的名字。旧副对话首次打开时排入同一个元信息任务；只有 title_manual=0 且标题严格等于首条用户消息前 30 字的会话可更新标题，其余一律只补 display_abstract。该识别条件来自当前截取规则，迁移前的人工命名存在误判风险，因此保留旧值、迁移备份和审计，不扩大为所有旧会话重新命名。没有成功首轮的会话暂不总结。

模型故障、预算不足或无效摘要不会影响已成功聊天。保留旧标题；新对话保留短占位并支持原有重命名，活动里记录失败。采用现有可恢复错误重试；不追加无限标题重试。菜单固定单行，超长手动标题以省略号和完整提示呈现，不能推开菜单操作。

点击导航搜索或对话栏搜索只打开 SearchDialog，底层 page、hash、当前会话、草稿、已打开详情和阅读位置不变。默认列最近二十个有效或封存话题；每行有主题标题、展示摘要和必要的封存标识。输入沿用 180ms 防抖，只按标题匹配，不搜正文、不联网、不调用模型。列表每次取二十条，可继续加载，保证旧话题可找到。Up / Down 选择，Enter 打开，Escape 或背景点击关闭并恢复触发处焦点。背景键盘和滚动被隔离。

打开结果后关闭弹窗并进入该对话。封存话题保持只读，明确解封后才能继续，打开搜索结果不能顺便解封。加载中、无结果和读取失败各自显示短文案，失败不伪装成空列表。旧的直接 #search 链接兼容为在聊天底页打开弹窗，不恢复那个替换整页的搜索界面。

**动态与来源，R03。** 动态页只有一个页标题，右上角 44px 可点击的“动态选项”按钮。菜单含“关注说明”和“管理来源”。关注说明复用已有编辑弹窗，保存只影响尚未排入的未来生成，不重写历史内容。管理来源弹窗直接列出 OpenAI、Python、NASA 三项；未关注显示“关注”，已启用显示“暂停”，停用显示“恢复”。同时说明首次尚未检查、最近成功时间或实际读取失败原因。已关注项目不再被当成新增项目提交；重复关注保持幂等。

删除本页准备简报、检查来源、生成关注内容，以及显眼的内联关注说明编辑区。保留单条关注内容的阅读、真实来源与继续讨论能力。来源失败以简短状态提示引导到来源管理，无手动检查按钮。公共资料说明只基于 RSS 摘要，不声称读过全文。

自动生成使用当前关注说明、本机真实事项和本次实际取得的来源。每日整理为零至五条独立的关注内容，标题表达具体内容，正文避免把整份诊断报告铺成一条。公共信息每条关联输入中的实际来源条目及发布时间；来源与时间由 Gateway 回填，模型不能自行编造。原始 RSS 作为素材保留，首页不重复铺原始素材和生成内容。本机事项仍可混排，已投递提醒继续留在原会话。当天没有相关材料时记录无更新，不插入“没有资料”文章。

**每天 06:00 的生成规则，R03 / R05。** 在现有 Gateway.tick 中计算当前时区最近一个已经到达的本地 06:00。持续运行时在到点后的一个调度周期内排入 feed 和 ideas 两个作业，沿用单 worker。机器关闭期间无法执行，恢复时各补最近一个时间点，不回填所有漏掉的天。首次启用也按最近到达的时间点补一次。06:00 表示自动触发时刻，完成时间取决于现有作业及 API 响应。

两类作业分别使用 daily:feed:本地日期、daily:ideas:本地日期 的唯一 trigger_key。重启、重复 tick 和恢复都不能为同一日期重复排入；重试属于同一作业的新尝试。日期和时区写入作业输入及配置快照，不以 24 小时间隔推算下一天。保存实际 generated_at，Feed 按实际生成时间分组，补做不能显示成已经在 06:00 完成。优先处理交互聊天，标题和自动内容使用后台优先级。来源继续遵守 12 秒、2 MB、固定目录和禁止跟随重定向的现有约束。

未填写关注说明时，Feed 当次记为无生成并提示去设置，不能持续报错或反复入队；构想仍可从已接入的能力及真实本机上下文生成。自动作业沿用 feed / ideas 的只读工具白名单，允许检查资料，禁止保存目标、记忆、安排提醒和导出文件。正常每类内容一次生成请求；格式不符最多纠正一次，所有请求与元信息生成都计入现有预算。预算用尽或模型网络失败时保留已发布内容。来源全部失效时，不发布依赖这些来源的公共信息；真实本机事项和无需外部材料的构想仍可生成，状态注明来源失败，不能把失败当成“无更新”。后台生成不发通知、不创建特殊聊天。

页面显示“每日 06:00 更新，需本机运行”及必要的失败状态，构想条目仍无时间戳。当前批次、最近成功和下次到点可在已有活动 / 状态里核查。通过隐藏按钮实现不了这一条，自动排入、真实生成、校验及发布必须一起完成后再删除旧入口。

**五条构想与立即开始，R04 / R05 / R06。** ideas 作业要求五个独立对象，逐项校验：具体标题不超过 24 字、单句 abstract 不超过 60 字、以“我帮你……”说明的正文不超过 400 字、最多三项交付内容和简短运作方式。每条有受支持的 action_kind 和实际 context_refs。支持方向限定为目标拆解、来源摘要、文档草稿、下一步整理、现有任务复盘。没有个人资料时提供能力范围内的起步构想，不能杜撰个人目标，也不能承诺邮箱监控、浏览器执行、交易或未接入服务。

标题必须区分五条内容，拒绝把“下一步建议”“构想”“建议清单”作为标题。五条全部有效后，Gateway 在提交作业成功的同一事务里写入新批次，将原批次标为 superseded。当前列表只取 active 批次，固定五条。老记录保留 ID、来源和审计，已有引用仍可打开，页面不再累积旧建议。不能把一段长回复机械切成五段来通过数量验收。

生成不完整、重复、没有真实关联、越过能力范围或被取消时，整批不发布，旧五条不受影响。重试同一作业不能再插入五条。当前历史只有三条的过渡状态，在首个有效新批次产生前如实保留，成功后统一成为五条。

列表用简短标题和摘要表达结果，去掉准备构想、时间戳与诊断式依据长文。点击条目打开 IdeaDialog，保留底层构想页。弹窗展示标题、我能交付什么、包含内容、如何开始，只有“现在就开始”主按钮和关闭操作。移除带引用讨论、提出修改和设为目标三个附加入口。

“现在就开始”向服务端提交条目 ID 和本次 request_id。Gateway 确认条目属于当前批次，从受限 action_kind 及服务器保存的内容构造开始指令，原子建立副对话、保存用户开始消息并排入工作，前端直接显示执行进展，用户无需再点发送。双击只产生一个会话和作业。旧批次在点击前已经失效时返回 409 并刷新列表，不悄悄启动另一条建议。按钮仅授权该条工作范围，引用内容继续作为资料处理。

首个成功回复应给出该构想的首份可用结果；缺必要输入时只问一个必要问题。目标保存、持续提醒和文件落盘继续遵守相应的明确确认及审批。文档可以先在聊天 / 成果库形成草稿，批准后才写入 data/exports。生成器不能用“我已完成”代替真实工具回传。

**成果库，R08。** 列表和详情只提供标题、适量预览、查看及下载，不显示准备简报、引用讨论或指向生成的空态按钮。详情按当前实际格式展示 Markdown / 文本，不追加复杂媒体。草稿和已导出文件用已有真实状态区分。下载沿用现有接口，缺文件时提示实际失败，不提供失效下载。聊天中的文档生成及审批、下载授权边界继续保留。

**目标页及完成 / 取消，R09。** 无目标和追踪时，整个对应区块连同标题和占位文字隐藏，只显示目标页标题、右上选项以及纵向的“设定目标”分类。分类沿用健康、人际关系、财务、职涯、兴趣、生产力、其他，图标、标题和右箭头组成整行入口。

存在项目时，目标和追踪各只占一个紧凑区块。每行前有明确命名的勾选框，后面为一句话 abstract，去掉长正文、时间戳和引用按钮。新目标生成不超过 60 字的目标摘要，旧目标优先使用已存标题和首个完整目标句，不增加额外总结调用；超长内容只在行内截断，详情保留完整。必要的暂停状态可用短标识表达。

“追踪”取用户已设置且仍有效的任务，以及真实运行中的用户工作。同一 task_id 的排程和作业合为一行，不能同时出现两份。自动 Feed、构想和标题作业只在活动里呈现，避免每个清晨让目标页凭空出现追踪。勾选目标把它变为 completed，并结束 goal_id 精确绑定的持续任务和未决工作；勾选持续任务把任务变为 completed、禁用排程并结束未决工作；勾选无排程的正在运行工作表示结束追踪，实际取消作业，不假称模型完成了工作。

右上“目标选项”包含“查看已完成目标”。已完成目标弹窗可查看摘要，取消勾选恢复目标的 active 状态，已经结束的提醒保持结束，需要另行明确设置。恢复目标不能暗中恢复旧排程。取消的目标从当前页移除，保留审计和历史关系，不进入已完成列表，不新增回收站界面。

目标完成、取消和追踪结束共用 Gateway 的终止逻辑：先禁止新调度和未开始投递，取消可停止的待办及运行作业，使关联待审批动作与未投递 Outbox 失效，再落最终状态。已有不可中止的导出沿用删除对话的等待机制，期间显示“正在结束”，重启能继续收尾；已完成文件和投递历史保留。操作不能波及其他目标、无关联提醒或用户直接发出的独立工作。任何迟到模型结果都不得重新创建任务或投递。

**两三轮目标引导和并排聊天，R10。** 点击分类直接创建新副对话并自动发送类别开始消息，保留目标页并在左侧打开聊天。桌面可用宽度大于等于 1100px 时，导航后的区域按约 40% 聊天、60% 目标分配；这里不显示 240px 历史列。头像在聊天面板居中，两边各自滚动，输入框固定在聊天底部。提供展开完整聊天和返回并排的操作。较窄窗口改为目标 / 当前聊天切换，草稿、步骤和阅读位置保留，不把两栏压得无法输入。

引导作为持久的会话状态，由 Gateway 限制流程，Agent 在现有 Messages 接口返回经过校验的短问题、二至三个选项和目标草案。第一轮只确定方向，第二轮只补形成目标所必需的范围或频率，第三轮展示单句目标及“保存目标 / 调整一下 / 先不保存”。用户已经给出具体目标时跳过重复提问，一至两轮进入确认。计数以用户回复轮数为准，最多两次必要问题，然后进入确认；提醒、基线和详细行动方案在目标确定后才询问。

例如兴趣类别可先提供“每天短时阅读 / 每周整理笔记 / 自己说明”，选阅读后仅问一个频率或时长问题，再显示“每天阅读 10 分钟”的可保存目标。每次提问不能出现五项长问卷。用户明确说不要基线、不需要某细节时，不能再次强迫回答。选项是可点击控件，仍允许自由输入；调整目标进入同一草案，改变草案后旧确认作废。

结构化引导只生成问题和草案，尚未确认时不执行目标 / 记忆 / 提醒写入。点击保存由 Gateway 对屏幕上那一版草案执行确定性的保存，并显示真实记录回执；保存消息接入原会话。刷新或双击不能创建第二个目标。保存后给出“补行动步骤 / 设置站内提醒 / 暂不补充”选项。选择提醒先补缺失时间，再使用实际保存的 goal_id，不能让模型凭空抄写 ID。引导输出不合格最多纠正一次，仍失败时保留当前草案与步骤，显示失败，不伪造按钮或已保存状态。

自然语言路径同时修复：明确“确认目标：具体内容”应视为目标保存授权；单独的“确认”只在该对话唯一待确认草案存在时有效。“先不要保存”“只是讨论”“如何创建目标”等仍不授权写入。当前作业已经保存且用户明确指向“这个目标”的提醒请求，使用本次成功回传的 ID；明确目标名称必须唯一匹配。错误 ID 可在同一授权范围内纠正，不能要求用户重复授权，也不能把其他目标的 ID 猜进来。明确的保存、关联提醒与取消请求进入现有缺少工具回传的校正流程；校正后仍无成功回传则报告失败，不能以口头承诺结束。

新增 cancel_goal 与 cancel_tracking 工具，接受明确 ID 或完整名称。用户说“取消某目标”“停止某追踪”“删除这个目标”后调用相同终止逻辑，从页面移除条目。重名或指代没有唯一上下文时展示候选并问一个澄清问题，不执行。引用中的取消指令不能授权操作；“不要取消”不得触发。只有收到真实成功回传，Navi 才能说已经取消。

## 接口、持久状态及文件交接

保持当前本机 API 边界、JSON 修改请求检查和来源校验。新增接口只接受表中字段，ID 必须属于实际存在的记录和会话。内部批次生成不能通过公开 chat 的 kind 参数任意注入。

| 接口 | 确定的变更及返回 |
| --- | --- |
| GET /api/sessions/search | 保留数组返回和原有 q 标题搜索。增加 recent、limit、offset；recent=true 且 q 为空时返回近期话题，UI 的 limit=20，范围 1 至 100。无分页参数的现有 CLI / 工具检索继续覆盖全部匹配。返回 display_abstract，包含封存状态 |
| POST /api/ideas/{id}/start | 输入 request_id。原子校验当前批次并返回 session_id、job_id。重复 request_id 返回同一次工作；失效条目 409，找不到 404 |
| POST /api/goals/start | 输入 category、request_id。category 仅 health、relationships、finance、career、interests、productivity、other。原子建立引导会话和开始作业，返回 session_id、job_id；重复请求返回原结果 |

| POST /api/goals/{id}/state | 输入 operation，限定 complete、cancel、reactivate。返回实际状态、受影响任务及必要的 ending 状态。恢复只允许 completed 目标，不恢复已终止排程 |
| PATCH /api/schedules/{id} | 增加 operation=complete。保留 pause、resume、cancel；complete 和 cancel 使用共享终止逻辑，使关联待办停止。已结束任务不能通过 resume 复活 |
| 现有 record PUT / DELETE 和 update_goal | 目标的 completed / cancelled 转换必须走共享生命周期；删除目标转为取消并移除当前列表。其他记录维持现有行为，不能绕过关联取消 |

| 持久位置 | 字段和约束 |
| --- | --- |
| sessions，阶段一 schema v3 | display_abstract TEXT，默认空；现有 title_manual 保留。session_meta 使用唯一 trigger_key，只针对首轮及明确的旧自动标题；保存原题值到审计 |

| records.payload，阶段二 | idea 增加 batch_id、content_date、generated_at、state、abstract、includes、how_it_works、action_kind、context_refs；execution_prompt 由服务器构造。仅一个 active 批次含五条，superseded 保留。Feed 增加 origin、generated_at，区分 rss_material、generated、local，保留真实来源 ID 和日期 |
| records.payload，阶段三 | goal 增加 abstract、completed_at、cancelled_at、必要的 ending_to；state 允许 active、paused、completed、cancelled。草案只存在对应会话，确认后才成为 goal |
| 已有 tasks / schedules / jobs / audit | 不另建任务表或调度表。任务沿用 active、paused、completed、cancelled；每日日期去重使用 jobs.trigger_key，开始操作及卡片选择也使用已有唯一作业键 / 选择回执。恢复处理未收尾的 ending_to |

日批次的结构化输出先在 Agent 中生成和验证，Gateway 在作业最终成功事务里发布；取消状态优先。批次替换、卡片推进和确认落库都需要在同一事务里完成，避免刷新读到半套内容。结构化生成仅发送进度状态，不能把原始 JSON 流进聊天正文；验证并持久提交后才展示卡片，普通聊天继续沿用文本流。无新增配置开关；06:00 为固定规则，读取当前 timezone。auto_content 是由作业历史计算的只读状态，不能成为另一套调度设置。

## 实施顺序、验收与回退

视觉验收使用 1280 × 802 的内容区与表格 B 列对照，并补 900 × 700、375 × 812、320px 宽及 200% 缩放。聊天头像中心偏差不超过 4px；标题不挤出菜单；全页无重复摘要条；搜索确实覆盖原页面；构想详情为弹窗；目标并排和窄屏切换都能输入。与 Muse 对齐导航比例、阅读宽度、留白、控件位置和选项形态，保留 Navi 品牌，不新增礼物、测验或没有实现的图标。
