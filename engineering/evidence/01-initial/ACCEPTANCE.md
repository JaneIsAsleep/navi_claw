## 复现

先执行 `./test`。默认测试使用固定数据、受控时间与明确离线替身，不调用付费 API。最终运行记录有 30 项通过，包括来源去重、发布时间、失败与静默。前端 `npm run build` 的 TypeScript 检查与生产构建通过。Starlette 当前测试客户端提示 httpx 将来迁移，属于依赖弃用提示，未导致失败。

在本机设置页配置真实 DeepSeek 后执行 `./test --live`。它创建独立的 `engineering/verification/state/live-*`，加载 `engineering/verification/fixtures/check_items.json`，不修改日常记忆、目标或关注事项。验证真实工具往返、后台到期、严格拒绝与批准、扩展切换、真实 Agent 导出提案、长历史压缩继续、日常提醒自动投递、Python 官方 RSS 与重建 Gateway。所有付费调用计入项目每日限制。完整输出在 `engineering/evidence/04-muse-revision-v1/implementation/live-evidence.json`，最终状态为 `passed`。RSS 内容会随发布变化，证据记录当次实际条目。

固定长历史由验收程序预置，用真实 API 总结并继续。它减少购买无意义对话的次数，证据中区分固定输入和真实模型结果。可靠性中的取消、超时、暂时失败及异常恢复采用受控离线测试，清洁停止与重启另有实际进程证据。

启动与关闭验证记录在 `runtime-evidence.json`。它检查重复启动相同 PID、后台无终端且由 PID 1 托管、停止后端口断开、新实例启动后状态 ID 保留，以及 CLI 与 Web 共用状态。用户另已实际确认关闭启动终端后网页正常，此项来源单独记录。运行 `./.venv/bin/python engineering/verification/scripts/runtime_acceptance.py` 可重做进程与跨通道检查，前提是先通过界面创建名为“界面验收周期任务”的暂停周期任务；该检查会停止并重新启动当前 Gateway。

界面验收实际创建了固定目标、测试记忆、暂停周期任务、批准并下载的文档，以及已拒绝提案。拒绝后对应文件数量为零，批准文档投递数量为一。Python 官方订阅的保存、刷新、暂停、恢复和手机布局通过；真实建议引用了固定目标与偏好。直接网址切换和浏览器后退通过。记录与 Navi 自身截图在 `ui-evidence.json` 及 `engineering/evidence/01-initial/screenshots/`。交付时固定测试状态停用或暂停。个人数据目录不应随课程源码提交；证据使用固定文本和公开来源，均不含密钥。

完整源码、原始 PDF、计划、锁文件、启动/测试入口与证据均在同一个项目目录。前端已构建供当前机器启动；从干净源码运行时先执行 `./setup`。

快速重启的回归测试在修复前实测失败、修复后通过。原因为 HTTP 已断开时旧进程仍持有单实例锁；停止器现在等待已验证身份的 PID 真正退出，只发送信号 0 查询存活状态。检查了启动、停止、状态三处 health 使用：修改停止判断，保留启动的归属/端口/就绪检查和服务端单实例锁。实机立即重启通过。源码尚未提交或推送。

开发早期存在未计入缓存输入的调用记录。最终版本已修复并通过流协议及真实调用验证，后续用量包含缓存输入；历史开发累计数据不能作为精确账单，费用以服务商账单为准。
