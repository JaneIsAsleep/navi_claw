# Navi 开发日志

这里记录需求、方案选择、实施问题与验证结果。版本功能概览见 [版本记录](CHANGELOG.md)。2026-10-08 之前的条目依据现存计划和验收材料补录，阶段日期不代表当时已经创建 Git 提交。日期使用台北时间。

## 2026-10-01 至 2026-10-02 初始 MVP

依据：[Navi 开发与验收计划](../plans/Navi_plan.md)、项目原始要求 PDF，以及初始提交 `0dd28f5` 中的 `docs/ACCEPTANCE.md`，其材料现保存在 [初始验收记录](../evidence/01-initial/ACCEPTANCE.md)。

这一阶段先建立能够持续运行的本机个人助理。技术路线为 Python 3.12、FastAPI、SQLite、React、TypeScript 和 Vite，CLI 与 Web 通过同一个 Gateway 操作同一份持久状态。真实模型接入采用 DeepSeek。

定时任务、Heartbeat、会话压缩及简报 Skill 共用作业执行和审计链。普通站内提醒采用用户授权的日常策略，同时保留课程演示所需的严格逐条审批策略；文档导出执行前须审批。云端虚拟机、完整影音及跨网站交易操作没有纳入本轮范围。

初始验收材料记载 30 项离线测试通过，并保存了真实模型、后台进程、CLI/Web 共用状态和界面操作证据。这些属于当时结果，本次没有重新运行初始版本。

2026-10-02 创建初始提交 `0dd28f5`。此后两轮实现一直保留在工作区，直到 2026-10-08 才保存为新的 Git 基线。

## 2026-10-03 至 2026-10-04 产品细化实施

依据：[产品细化验收记录](../evidence/03-refinement/ACCEPTANCE.md)。

这一轮增加主对话保护、副对话管理、提醒路由、统一审批和关联记录。封存话题的提醒转入主对话；删除话题前展示关联影响，删除后结束相关工作。审批保存正文版本和历史，防止修改后的动作沿用旧批准结果。前端同步调整导航、助手详情、窄屏状态及弹窗键盘操作。

数据迁移保留旧会话和消息，缺少来源的旧记录显示为无法确认关联。迁移前使用 SQLite 备份，CLI 和 Web 继续共用同一 Gateway。

真实模型检查曾出现“回复已经设置提醒，但系统没有对应调度记录”的失败。修复后，对用户明确委托的可用工具检查实际成功回执；缺少回执时纠正一次，仍未完成则报告失败。相关回归还检查已保存记忆不会因纠正而重复创建。

2026-10-04 的历史离线结果为 53 项通过，新增七组真实模型闭环通过。真实工具、提醒归属、审批后导出和删除收尾均保留证据。界面与部分运行检查使用隔离固定数据；一周真实试用仍待完成。

阶段证据：[首次真实失败](../evidence/03-refinement/live-initial-failure.json)、[后续闭环结果](../evidence/04-muse-revision-v1/implementation/refinement-before-revision.json)、[启动与恢复记录](../evidence/03-refinement/phase4-runtime.json)。这些文件记录当时执行结果。

## 2026-10-08 至 2026-10-09 Muse v2 实施

依据：[Muse v2 计划](../plans/Navi%20Muse%20Revision%20Plan%20v2.md)、[五阶段实施验收](../evidence/05-muse-revision-v2/implementation/ACCEPTANCE.md)。本条于 2026-10-09 按用户授权补录，实施结果沿用原日期和证据。

V2-01 先修复 L01 至 L04。目标修改按当前明确请求逐字段授权，到期任务禁止修改目标；无关提醒不继承旧目标；Heartbeat 仅在 active/paused 时占用名额；构想原会话删除后返回 410，前端只在该响应下更新请求 ID 并重试一次。最初的隔离回归得到 12 项失败、2 项通过，修复后通过。随后增加 schema 5 迁移、连续清醒 60 秒门槛、10/30 分钟有限恢复、跨日接替及累计调用限制。个人数据先备份再迁移，取消本地每日总量拦截，保留用量记录、单作业限制和提供商额度约束。

V2-02 完善类别说明、目标引导和聊天面板。关闭说明不保存，明确开始后进入持久选项引导；桌面和窄屏切换保留草稿与卡片。完成目标立即结束关联工作，完成行约三秒后移走；失败恢复勾选，恢复目标不复活旧提醒，移除已完成目标保留相关会话、文件和审计。

V2-03 为 Web 增加正文搜索、命中片段和消息定位，CLI 沿用标题搜索。检索及查看均不调用模型。搜索弹窗在加载、不同结果数量和读取失败时保持尺寸，分别验证鼠标、键盘及混合操作后的焦点。Chromium 与 Safari 的实际环境和测量范围单独记录，Safari 窄宽检查没有描述为手机模拟器。合成数据包含 2000 个会话、100000 条消息，完整 API 搜索 p95 为 301.65ms，属于该次测试环境的结果。

V2-04 接入公开 HTTPS RSS/Atom 的预览、确认添加及暂停、恢复。确认时再次读取，修改地址后清除旧确认；原三个官方来源及其 ID 保留。校验公开 DNS 地址、重定向、连接目标、TLS 主机名、大小与超时限制。来源预览和管理使用真实 HTTP，无需模型；GitHub 官方 RSS 读取与对应界面闭环有独立记录。

V2-05 完善图文动态、分页和引用讨论。正文优先使用订阅正文，必要时补读来源提供的文章，保留实际读取范围；通常两段、140 至 300 字，资料不足允许短文。配图来自真实材料，无图时保留彩色图标；分页和图片读取不调用模型。讨论先形成待发送引用，用户发送后才创建聊天作业。桌面并排、完整聊天与窄屏切换保留草稿、引用和阅读位置。

第五阶段曾发现隐藏动态面板的后台轮询覆盖阅读位置，以及真实模型引用材料 ID、正文长度和否定保存请求的错误。修复后重新验证，失败运行与成功运行分别保留，没有覆盖失败证据。
