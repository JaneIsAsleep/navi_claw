# Muse 核心体验与视觉验收

开发前与主要界面完成后，均使用本机 Muse 观察聊天、目标、动态、构想和成果入口。观察只作为产品与视觉参考，未把 Muse 私人对话迁移到 Navi、模型输入或提交证据，也未把产品建议文案当成能力证明。

Muse 桌面窗口截图为 2560 × 1604，逻辑尺寸为 1280 × 802。Navi 在同样逻辑尺寸下对照目标页，另检查 1280 × 800、375 × 812、320 × 740。截图保存为 Navi 自身的测试状态，未保存 Muse 的私人内容到仓库。

| 对齐项 | Navi 实现与检查 |
|---|---|
| 聊天为中心 | 独立导航、会话列表、阅读区域和底部圆角输入；真实流式进度与完成消息 |
| 留白与层级 | 白色阅读面、温灰导航、淡蓝用户气泡、灰色助理气泡、系统中文字体，列表采用分隔线 |
| 记忆与个性化 | 有效记忆进入后续上下文，可编辑、停用、删除；建议保存实际依据 |
| 目标持续跟进 | 状态、下一步、关联调度与成果；独立跟进入口 |
| 动态与建议 | 本机事项与英文官方 RSS，分别显示发布与检查时间；实际模型结合目标、偏好生成建议 |
| 轻量成果库 | 保存实际简报草稿和审批导出的文件，可查看及下载 |
| 用户掌握行动 | 待批内容与目标可见，修改后重新审批，拒绝零执行，批准后显示实际投递 |
| 窄屏与键盘 | 折叠导航和会话列表，375/320 无横向溢出；弹窗 Escape、焦点约束和返回焦点 |

2026 年 10 月 3 日细化开发按已确认计划采用六入口窄图标栏，名称在 hover 和键盘聚焦时出现，触屏通过展开菜单显示。Navi 自制静态球形标识承接助手详情，四个标签集中跟进、审核、提醒和身份，记忆位于身份内。这里的更新覆盖旧版可读文字导航说明，原历史验收文件仍保留。

本轮再次以实际 Muse 窗口和入口作为布局参考，采用相同的 1280 × 802 逻辑尺寸检查 Navi，另检查 375 × 812 和 320 × 740。只保存 Navi 独立测试数据的截图，见 [本轮验收](../evidence/03-refinement/ACCEPTANCE.md)。Muse 的实际封存转发送达和删除规则没有作为已验证事实；Navi 的 Q01 与 Q02 依用户决定实现并独立测试。角色素材、声音和娱乐能力未复制。

已实际检查空会话、真实中文与长哈希消息、目标保存、任务关联及暂停、待审批与拒绝/投递状态、成果下载、记忆保存、真实个性化建议、订阅保存与暂停恢复、加载进度及断开后重连设计。动态页在 375 像素宽度没有横向溢出。直接链接与浏览器后退会同步当前页面，无效页面名称回到对话。当前话题菜单的长标题采用单行省略和完整名称提示，内容正文仍可断行。交互反馈限于短按压，尊重减少动态偏好，没有布局位移动画。

开发辅助使用已有 `ui` 技能及其设计参考，React 使用 CSS Modules 和 lucide 图标。未额外安装全局技能。运行时 `skills/priority_briefing` 与 `skills/deadline_briefing` 为项目自有简报扩展，已分别参与真实验收。

范围保持用户已确认的边界：云端虚拟机、完整影音/Podcast 工作流、跨网站购物/退款/取消订阅不纳入本次交付。外部动态保留三个英文官方 RSS，并支持用户确认的公开 RSS/Atom；仅补读订阅已经提供的公开文章链接与配图，不增加任意网站搜索或账号内容访问。生成内容基于实际读到的资料，其表达质量与事实完整性仍需要结合原始来源判断。
