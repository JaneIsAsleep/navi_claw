## 2. 项目定位与答辩主线

建议项目标题：**Navi：基于 MiniClaw 的本地持续运行个人 AI 助理**。英文标题候选：**Navi: An Always-on Personal Assistant for the MiniClaw Course Project**。

项目关注一个具体问题：用户通过聊天交代了一项持续任务后，仍需要系统按时执行、保存进度、识别值得提醒的变化，并在发送结果或写入文件前提供可检查的审批过程。一次对话结束后，任务的生命周期仍然存在。

Navi 采用本机单用户应用。CLI 与 Web 访问同一个 Gateway，SQLite 保存会话、任务及执行记录。调度器创建到期作业，Agent Adapter 调用真实 DeepSeek API 和本地 Skill，Gateway 负责权限判断及获准结果的投递。课程验收演示采用严格逐条审批策略。

答辩围绕一条任务展开：用户安排周期简报，关闭页面后 Gateway 继续运行，到期生成作业，Agent 使用 Skill 结果形成简报，用户审核具体内容，获准结果进入 Outbox 后完成投递，重启后仍能查看相同任务与记录。补充展示一次拒绝操作，说明系统如何阻止投递。

这条流程可以同时解释需求、模块职责、对象关系和验收方法。记忆、目标及界面体验提供辅助背景，有限的答辩时间优先用于课程核心机制。

**中文摘要草稿：**

> Navi 是面向 MiniClaw 课程项目的本地个人 AI 助理。系统通过持续运行的 Gateway 连接 CLI 与 Web，统一保存会话、调度及作业状态，并调用真实模型 API 与本地 Skill 执行周期任务和 Heartbeat 检查。可见行动经过审批后进入 Outbox，拒绝的行动不投递。项目将通过完整任务流程、异常分支和重启恢复验证功能，并进一步评估持续使用体验。

正文、PPT 和讲述采用中文。原通知用 words 表达摘要长度，不能将中文字数直接等同英文词数；中文摘要的正式计数口径尚未说明，排版时保留核对项。下列英文摘要为备用，当前为 127 词，不默认同时放入正式的 6 页 proposal。

**英文摘要备用：**

> Navi is a local personal assistant developed for the MiniClaw course project. It addresses the need to keep planned work active after a conversation ends while allowing users to review actions before execution. A persistent gateway connects a command-line interface and a web interface to shared sessions, schedules, jobs, and delivery records. An agent adapter calls a real language-model API and a local workflow extension to generate useful results. Recurring tasks and heartbeat checks support background work, while approval and outbox mechanisms control delivery. The project uses Python, FastAPI, SQLite, React, and TypeScript. Evaluation will trace a complete scheduled workflow, test rejection and failure handling, and verify state recovery after restart. The team will prioritize the required workflow, then validate selected advanced capabilities within the same architecture.

## 3. 功能、需求与设计内容

按旧课件第 5 页要求，准备以下 4 个用户故事，并转化为正式 UML 用例图和关键用例说明。用户是主要参与者，模型服务是外部参与者；周期触发可在用例说明中描述，避免将系统内部模块混作用户。

| 用户故事 | 对应用例 | 可检查的结果 |
|---|---|---|
| 作为用户，我希望安排周期简报，在停止聊天后仍能按约定执行 | 创建、查看和管理周期任务 | 无新消息时创建到期作业，保存状态与结果 |
| 作为用户，我希望定期检查关注事项，仅在有新变化时得到提醒 | 配置 Heartbeat、检查事项、审核提醒 | 无事保持静默，有变化形成待审批行动 |
| 作为用户，我希望在结果发送或文件写入前看到具体内容，并可以拒绝 | 查看、批准、拒绝和修改行动 | 批准后进入 Outbox，拒绝后零投递，修改后重新审批 |
| 作为用户，我希望在 CLI 与 Web 间切换，并在重启后继续查看任务 | 访问共享状态、查询执行历史 | 两通道看到相同记录，干净重启后关键状态保留 |

功能优先级依据 MiniClaw 原始要求 PDF 的两页内容确定。Basic 共 70 分，为必需范围；Advanced 共 30 分，为可选范围。当前 Navi 批准计划包含全部 Advanced，答辩只能将有证据的项目表述为已实现。

| 优先级 | 功能范围 | 材料中的呈现方式 |
|---|---|---|
| P0 必需 | 持续 Gateway 与 CLI、身份与状态、周期作业、Heartbeat、审批与 Outbox、真实 Agent 和至少一个扩展、测试与文档 | 逐项对应需求与验收，构成主流程 |
| P1 进阶 | 独立 Web Adapter、取消与超时、恢复及防重复、可替换扩展、长会话压缩、任务生命周期、审计 | 对照已有实现复核，正文概括，证据放附录 |
| P2 体验补充 | 记忆、目标、历史会话管理、关注内容和成果入口 | 展示与核心任务相关的少量页面，控制讲述时间 |
| 范围外 | 云端虚拟机、复杂影音生产、跨网站购物退款、未经另行授权的外部渠道接入 | 在范围说明中简要交代，避免追加承诺 |

非功能需求需要给出可验证目标。下表是开题验收方案，具体性能结论需要本次测量支持。

| 维度 | 目标与验证方法 |
|---|---|
| 性能 | 测量本机状态查询、到期触发延迟和模型响应时间，报告测试条件及实际耗时。现有单次模型请求超时为 60 秒，单作业期限为 180 秒，二者属于限制参数 |
| 结果可信性 | API 失败保存失败作业。明确工具委托须有成功工具回传，文字回复与执行记录共同核对 |
| 持久化 | 干净重启前后比对用户、会话、调度、作业和投递记录的稳定 ID 与状态 |
| 权限与可靠性 | 拒绝零投递，旧版本批准失效，同次触发及重复审批不造成重复执行 |
| 存储 | 本机 SQLite 保存结构化记录，导出成果另存文件。测量固定样例的数据量与数据库大小，说明历史记录增长及备份方式 |
| 成本 | 记录一次完整演示的 API 请求数和实际 token 用量。按演示时核实的官方价格估算费用，并保留调用预算。部署使用现有电脑，硬件与网络条件单独说明 |
| 可用性 | 验证启动、停止和状态入口，以及关闭页面后后台继续运行。电脑休眠和 Gateway 停止期间无法执行检查，恢复边界需明确 |
| 隐私 | 说明哪些上下文发往模型 API。密钥不进入提交材料、截图、日志和证据，演示使用独立样例数据 |

设计材料应体现 OOAD 课程关注的职责划分，避免仅展示技术栈名称。

| 设计材料 | 具体准备内容 | 检查重点 |
|---|---|---|
| UML 用例图及说明 | 对应 4 个故事，补充批准、拒绝、API 失败等分支 | 每个用例能追溯到用户需要和验收条件 |
| 架构图 | CLI/Web Adapter、Gateway、Agent Adapter、DeepSeek、本地 Skill、SQLite、审批与 Outbox | 两通道共用状态，权限由 Gateway 控制 |

| 时序图或活动图 | 从周期触发到作业、扩展、模型、行动提案、审批、Outbox 与投递 | 明确等待审批、拒绝和失败发生在哪一步 |

技术路线沿用批准计划：Python 3.12、FastAPI、SQLite、React、TypeScript、Vite、真实 DeepSeek API 和本地 Skill。单进程 Gateway 服务构建后的前端，并通过两个 Adapter 提供访问。开发辅助工具与应用运行时扩展分别说明，答辩中的扩展证据来自 Navi 实际加载和调用的 Skill。

原始 PDF 对 Heartbeat 通知及可见行动要求发送前审批。Navi 同时保留日常普通提醒自动授权与严格逐条审批两种策略。课程主演示使用严格策略，明确这一实现选择及日常策略差异，评分接受程度需以教师意见为准。

| 风险 | 对方案的影响 | 准备措施 |
|---|---|---|
| 今年课程要求与旧课件不同 | 页数、语言、日期或验收范围可能调整 | 先完成需求差异表，收到今年要求后统一更新全部材料 |

| 模型回复与实际执行不一致 | 任务创建或修改可能只停留在文字层面 | 同时检查工具回传和持久记录，保留失败及纠正案例 |
